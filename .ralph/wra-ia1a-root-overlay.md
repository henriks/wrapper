# Epic wra-ia1a: Replace Docker-only data disk with persistent VM root overlay

Implement the intended VM persistence model: immutable appliance rootfs plus a project-local persistent writable overlay for the guest root filesystem. Docker should use the same persistent root overlay unless live validation proves a separate Docker disk is required.

## Goals
- Replace Docker-only persistence with persistent root overlay storage.
- Keep `docker/out/rootfs.raw` immutable/read-only as the lower rootfs.
- Make ordinary guest writes, home/tool installs, caches, `/usr/local`, and `/var/lib/docker` persist across relaunch.
- Add live validation for ordinary persistence and Docker persistence.
- Remove `.sandbox/home` special-case persistence once overlay root is working.
- Keep docs and ticket notes current.

## Notes
- Current implementation creates `.sandbox/docker-vm/state.raw`, formats it ext4 on first launch, attaches it as `/dev/vdb`, and `docker/guest-init.sh` uses it as the persistent root overlay state disk.
- Current rootfs is attached read-only as `/dev/vda`; `agentvm-init` mounts it as the immutable overlay lower and re-execs into the overlay root.
- `.sandbox/home` is no longer generated as a composed-fs persistent-home mount; guest `$HOME` lives on the root overlay unless covered by explicit tool/user shares.
