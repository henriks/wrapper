# Add composed filesystem operation model tests

Build an exhaustive model/property-style test suite for composed filesystem operations. The suite should compare composed-fs behavior against a real tempdir model where semantics are intended to match, and explicitly assert different behavior where composed-fs intentionally diverges.\n\nOperation coverage: lookup/stat, read empty/small/large files, offset reads, EOF, binary content, repeated reads, create, overwrite, append, truncate, mkdir, rename, unlink, rmdir, fsync/no-op semantics, directory listing, nested paths, host-side mutations, and error mapping for not found/not dir/is dir/permission denied/readonly/invalid path.\n\nInclude readonly enforcement for user RO and system mounts, cross-mount boundary behavior, symlink policy/escape prevention if symlinks are supported or traversed, host reflection for RW mounts, and deterministic behavior for overlapping or duplicate targets.\n\nRelevant code: composed-fs crate and any vm-frontend code that generates composed-fs manifests.

## Acceptance Criteria

The model suite exercises both successful operations and error cases across RO/RW/system mounts. Failures report the operation sequence and expected/actual result. Closing notes summarize coverage, intentional semantic differences from the host filesystem, and any remaining gaps.
