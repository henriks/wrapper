# Run guest payloads as the host-mapped user instead of root

Guest payloads currently appear to run as root. docker/guest-init.sh is PID 1/root, and docker/guest-payload-server.py launches /bin/sh -c <script> without dropping uid/gid. That means Codex and other tools may perform filesystem operations as guest root through composed-fs. Even if the backend maps to host syscalls as the host frontend process, root-visible behavior in the guest can bypass normal app assumptions and can create permission/mode surprises in guest-visible state.

The desired model is that the guest payload runs as a user matching the host user identity as closely as the appliance allows. Guest-visible HOME should be the natural host home path, and file ownership/mode behavior should be predictable for host and guest Codex processes.

Relevant code/docs:
- docker/guest-payload-server.py run_payload uses subprocess.Popen([...], cwd=cwd, env=env, preexec_fn=os.setsid) with no setuid/setgid.
- docker/guest-init.sh starts the payload server as root.
- vm-frontend/src/main.rs guest_payload_env sets USER and LOGNAME from host USER but this is only environment, not uid/gid.
- composed-fs/src/lib.rs attr_from_metadata reports host uid/gid in FUSE attrs.

## Design

- Create or select a guest user corresponding to the host user/uid/gid passed by the frontend.
- Ensure guest-init creates the natural home path and required directories with correct ownership before starting payloads.
- Drop privileges in the payload server before exec, or run the payload server itself as the target user while retaining only the privileges needed for init-owned services elsewhere.
- Keep Docker access working if the payload needs docker CLI access.

## Acceptance Criteria

- A guest payload running id reports the expected non-root uid/gid/user.
- Codex payloads run with HOME at the natural home path and without root uid.
- Files created in guest-visible workspace/home paths have expected host-visible ownership and modes.
- Tests or live self-test coverage catch accidental root payload execution.
- Docs describe the guest user identity model.

**2026-05-14T22:00:49Z**

Implemented host-mapped payload identity. guest_payload_env now passes AGENTVM_UID/AGENTVM_GID from the host process and uses the guest TCP Docker bridge as DOCKER_HOST so non-root payloads can still use Docker. guest-payload-server.py validates the uid/gid pair and drops privileges with setgroups/setgid/setuid in preexec while still creating a new session. Self-test payload now asserts id -u/id -g match the provided identity. Docs updated in requirements.md, docker/OPERATIONS.md, and docker/runtime-contract.md.
